# MyEnergy 项目章程

状态：首版方案 A 已由 Sponsor 于 2026-11-18 批准进入实现。日历工期、生产部署和发布不在本轮批准范围；实际状态见 status.md。

## 项目目标

开发一款仅面向 Apple 设备的个人状态与减压产品。用户可在 macOS、iPhone、iPad 和 Apple Watch 上查看自己的状态，并在同账号设备间延续使用。产品参考“小乖解压／BodyMood”所在的需求方向；名称、界面和内容独立设计。

首个可验收版本要回答两个问题：用户能否方便地记录和回看自己的状态；四类设备能否在明确的隐私边界内互联。健康数据的展示和解释以平台能力、数据质量及政策核查结果为前提。

## 已批准首版范围

用户已批准方案 A 进入实现。以下为首版范围，逐项实际验收见 status.md 和验证报告。

| ID | 候选功能 | 建议边界 |
| --- | --- | --- |
| F01 | 今日看板 | 展示主观精力、心情、今日习惯及最近记录；说明来源、更新时间和同步状态 |
| F02 | 精力与心情记录 | 精力 0～100 自评、心情五档，可选短备注；支持快速记录、回看、修改和删除 |
| F03 | 健康习惯 | 支持创建、编辑、停用习惯，以及当天完成和撤销；日期归属规则需统一 |
| F04 | 恢复参考 | 按需读取 HRV、静息心率、睡眠摘要；与自评分开展示；缺数据时显示原因，不生成推测值 |
| F05 | 设备互联与同步状态 | 同产品账号仅同步用户明确选择的记录／摘要；离线可记录，状态和失败处理可见 |
| F06 | 趋势 | 展示最近 7 天／30 天自评趋势及习惯统计；缺失日不伪造 0 分 |
| F07 | 数据控制 | 支持清除演示数据、导出本人数据、删除记录和账号；明确每项操作的范围 |

Apple App Review 5.1.3 已核实：应用不得在 iCloud 存储个人健康信息。项目保守地把心情、精力和健康衍生指标纳入敏感健康信息边界；关闭应用对这些数据的 CloudKit 自动同步，并对敏感本地文件设置和验证排除备份标记。该标记不能保证系统绝不备份，残余行为须在真机核查并披露；不能因私有库、摘要或加密而默认豁免。[Apple 官方规则](https://developer.apple.com/app-store/review/guidelines/#health-and-health-research)

推荐方案 A：SwiftUI 原生四端、本地存储、独立加密同步服务及 Sign in with Apple。健康原始样本留在设备 Apple Health，跨设备传输应用记录和摘要需单独授权。此方案已批准；生产设备撤销、密钥轮换、服务部署和元数据保护仍需专项验收，当前不能宣称已具备生产可用的端到端加密。

推荐 iPhone 作为主要健康入口，Watch 作为 iPhone companion，iPad 运行时检查健康能力；Mac 展示用户选择同步的摘要。建议最低版本为 iOS／iPadOS 17、watchOS 10、macOS 14，实现时核实 API availability。完整提案见 [首版范围与架构提案](../design/mvp-proposal.md)。

首版暂不纳入医疗诊断、疾病预测、治疗建议、付费 AI 服务、社交排行或 Apple 以外的平台。新增这些范围需单独评估并由 Sponsor 确认。

## 验收标准草案

本表用于讨论验收口径。G1 通过前，具体阈值和设备矩阵仍可调整；未确认项不能在收尾时直接视为通过。

| ID | 验收对象 | 可量化的候选标准 | 证据 |
| --- | --- | --- | --- |
| AC01 | 平台覆盖 | 在确认的最低系统版本及测试设备矩阵中，四类客户端均完成安装、启动和核心页面访问；每项结果可追溯 | 设备与系统版本、构建记录、演示或截图 |
| AC02 | 快速记录 | F02 获批后，从主界面新增一次默认精力／心情记录不超过 3 次主要操作；精力限制为 0～100，心情五档；取消不保存，保存后重启仍可读取 | 操作步骤及持久化测试 |
| AC03 | 记录生命周期 | 新增、修改、删除、重启恢复和失败重试各至少 1 个场景，全部符合已批准规则 | 场景与结果对照表 |
| AC04 | 习惯日期 | F03 获批后，重复完成与撤销不产生重复记录；跨午夜、切换时区、夏令时变化和手动调时各至少 1 个用例，归属日期符合已批准规则 | 时间场景测试记录 |
| AC05 | 跨设备互联 | 对获准同步的记录执行至少 20 个双设备场景，覆盖离线后恢复、并发修改和删除冲突；传输完成后的结果全部符合 ADR | 场景、设备日志及最终记录对照 |
| AC06 | 同步可见性 | 排队、传输中、完成、失败及账号不可用等获批状态均有明确反馈；测试中不得把未完成的传输显示为完成 | 状态矩阵与界面证据 |
| AC07 | HRV 降级 | F04 获批后，授权可用、拒绝授权、无样本、样本过旧和样本不足各至少 1 个场景；后四类不得伪造恢复数值 | 健康数据测试夹具及真机记录 |
| AC08 | 数据边界 | 每个字段有存储位置、传输路径、删除方式和保留规则；政策禁止传输的数据在持久化、日志及同步检查中出现 0 次违规外传 | 数据清单、政策依据及检查结果 |
| AC09 | 可访问性 | 核心记录流程能用 VoiceOver 完成；所有已批准核心页面完成动态字体和文字对比度检查 | 平台逐项检查表 |
| AC10 | 交付收尾 | 已批准验收项全部有结果，阻断缺陷为 0；其余已知限制由 Sponsor 明确接受 | 验收清单、缺陷清单及接受记录 |
| AC11 | 趋势 | F06 获批后，7 天与 30 天窗口各至少 1 个含缺失日的用例；显示时区及日期归属符合规则，缺失日不得当作 0 分 | 聚合测试与界面证据 |
| AC12 | 数据控制 | F07 获批后，演示数据清除、本人导出、记录删除、账号删除各至少 1 个场景；删除后旧设备回网不得使记录复活 | 操作记录、导出检查与同步验证 |

G1 确认最低系统版本，以及同步耗时、数据新鲜度、HRV 最低样本要求的负责人和子设计评审点。对应增量进入验收前，必须给出可测试阈值；阈值应来自选定机制、可用设备和验证结果。

## 约束与假设

设计已获批，源码及本地验证已交付；真实设备和发布事项按阶段门推进。

Apple 开发者团队、签名、entitlement、Sign in with Apple 配置、真机和服务部署资源是否可用尚未确认。模拟器结果与真机结果分开记录。当前不承诺工期、人日、预算或商店审核结果。设计确认不包含付费、正式部署或 App Store 发布授权。

用户已接受个人自我观察定位、推荐平台分工和同产品账号方案。Apple 登录身份不能替代设备解密密钥。
