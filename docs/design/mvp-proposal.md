# MyEnergy 首版范围与架构提案

状态：Approved。用户于 2026-11-18 明确回复“按推荐方案进入实现”。批准首版方案 A 及分阶段交付；不包含付费、正式部署或上架授权。

## 用户已确认的要求

Apple-only；覆盖 Mac、iPhone、iPad、Watch；同账号互联；多 agent；按 PMP 流程推进；在 MyEnergy 新目录完成。

## 推荐的产品定位

帮助用户记录自己的精力和心情，观察恢复变化，逐渐形成轻量的自我照顾习惯。

精力与心情由用户自评。Apple Health 数据作为独立的身体恢复参考。页面始终区分主观感受、生理数据和产品解释；缺数据时不生成看似精确的状态分数。

“MyEnergy”是工作名，正式上架前再核查名称、商标和域名。设计使用原创图形，不复用竞品角色、素材或文案。

## 方案比较

| 方案 | 优点 | 代价 | 结论 |
| --- | --- | --- | --- |
| A．SwiftUI 原生四端＋本地数据＋独立加密同步服务 | 符合四端互联目标，Mac 可展示经用户同意同步的摘要，服务可本地开发 | 需要账户、密钥、服务运维与真机验证 | 推荐；分里程碑交付 |
| B．本地健康数据＋iCloud 仅同步非健康设置 | 服务维护少，健康数据边界更清楚 | Mac 不能直接读取 Apple Health，不能满足完整健康记录互联 | 可作为缩减范围方案 |
| C．跨平台 UI 框架＋独立服务 | 通用业务逻辑便于复用 | Watch、健康权限及各平台交互仍需原生适配 | Apple-only 首版收益较小 |

## 首版范围

| 功能 | 首版行为 | 验收标准 |
| --- | --- | --- |
| 今日看板 | 主观精力、心情、今日习惯、最近记录、数据来源和同步状态 | 无数据和演示模式可辨认，真实记录可见且可编辑 |
| 精力与心情记录 | 精力 0～100 自评；心情五档；可选短备注 | 四端使用相同模型，取消不保存，重启后本地记录存在 |
| 健康习惯 | 创建、编辑、停用习惯；当天完成与撤销 | 同一日重复点击不会产生重复完成；日期边界有明确规则 |
| 趋势 | 最近 7 天／30 天自评趋势和习惯统计 | 按记录时间和时区展示；缺失日不伪造 0 分 |
| 恢复参考 | iPhone／支持的 iPad 按需读取 HRV、静息心率、睡眠摘要 | 无权限、无数据、样本不足、过期均有真实状态；Mac 不申请健康读取权限 |
| 设备互联 | 同产品账号同步用户明确选择的记录和摘要 | 离线可记录；恢复网络可重试；重复同步幂等；账号隔离；删除不复活 |
| 数据控制 | 清除演示数据、导出本人数据、删除记录和账号 | 演示数据不写入 Apple Health；删除流程明确说明范围 |

首版不加入订阅、广告、公开社区和第三方 AI 心理对话。它们可进入变更申请，另评估成本与数据流向，不阻塞首个可验收版本。

## 平台分工

- iPhone：主要健康接入设备、随手记录、习惯管理、设备配对入口。
- Apple Watch：精力／心情快记、习惯完成、查看最近状态。默认作为 iPhone companion，离线记录进入本地队列。
- iPad：适配大屏的今日看板、趋势和记录编辑；运行时检查 Apple Health 的可用性。
- Mac：原生侧栏看板、趋势与习惯编辑；健康信息来自用户选择同步的摘要，不能伪装成本机 HealthKit 读取。

建议最低版本为 iOS／iPadOS 17、watchOS 10、macOS 14；实现时编译核实 API availability。未要求用户升级到本机 SDK 版本。

## 数据与账号

“同账号”定义为同一 MyEnergy 产品账户。建议使用 Sign in with Apple，iPhone、iPad、Mac 的 App ID 需在同一开发者团队下正确分组；Watch 通过已配对 iPhone 获得必要的会话和记录。

Apple ID 登录身份不等于跨设备加密密钥。新增设备需要经过已有设备的确认或用户恢复密钥流程。具体密钥恢复方案在账号与同步子项目的设计中单独评审，未完成前不得称为生产可用的端到端加密。

健康原始样本留在设备的 Apple Health。应用不对健康记录启用 CloudKit 同步；敏感本地文件设置系统提供的排除备份标记，并验证标记在数据库和文件操作后仍存在。该标记属于系统提示，不能承诺任何系统备份／恢复路径都绝不会包含这些文件；正式发布前须验证并披露残余限制。健康衍生分数、心情与精力记录保守按敏感健康信息处理，不因“摘要”“加密”而默认豁免。

独立同步服务接收客户端加密的应用记录；TLS、账户授权和端到端加密分别解决不同问题。服务只做账号校验、密文存取、游标与变更版本管理，不计算 HRV、不读取用户备注。服务元数据仍有泄露风险，安全评审不得只检查正文是否加密。

健康摘要跨设备传输需要单独的用户授权。未授权不上传，撤销后停止新上传，并提供删除已同步数据的路径。是否涉及当地敏感个人信息处理要求须在正式发布前确认。

## 技术模块

- 共享 Swift package：数据模型、精力与习惯规则、日期处理、恢复参考计算、同步协议与测试。
- 原生应用：SwiftUI，iOS target 同时服务 iPhone 和 iPad，另设 macOS 与 watchOS target。
- 本地持久化：选择明确关闭自动 CloudKit 同步的实现；敏感内容不写入日志。
- 健康适配：HealthKit 仅在支持的平台编译和运行；拒绝授权与空结果不可混为“已授权”。
- Watch 适配：WatchConnectivity 的前台消息和后台队列；不假设它能直接连通 Mac／iPad。
- 账号与同步：独立服务和可替换客户端协议；开发用身份与生产 Apple 身份完全区分。
- UI：共享视觉组件，各平台导航、输入、窗口尺寸和辅助功能按平台适配。

## 恢复参考的首版边界

首先展示最近 HRV 及与个人历史的对照，不承诺自动识别焦虑、愉悦等情绪。基线必须有足够的有效历史数据；阈值、样本过滤、时间窗和算法版本都要写入实现子项目规格。

样本不足时显示“正在积累数据”，数据过期时显示最近时间。不生成一个合成“情绪电量”与用户自评混用。用户无需手表也能记录精力、心情和习惯。

## 同步语义

各记录使用稳定 UUID；服务为每个账户生成单调递增的变更游标。客户端保留待发送操作及确认状态，重试不会重复创建。

习惯打卡以习惯 UUID 和用户选定日历下的日期键标识，完成与撤销均为带版本的操作。并发编辑同一记录应能发现冲突，不能只依赖设备墙上时钟静默覆盖。删除以 tombstone 参与同步，并有账户重置／删除代际，避免旧设备回网恢复已删除记录。

断网、会话失效、密钥缺失、服务不可用、已同步但尚未送达其他设备须有不同状态。刷新时间不等于测量时间，也不等于所有设备已确认收到。

## 分阶段验收

1. M0 启动与设计：章程、WBS、风险、体验与架构提案具备可审阅版本。用户确认推荐方案后进入执行。
2. M1 本地可运行：共享核心测试；Mac／iPhone／iPad／Watch 工程可构建；记录、习惯和趋势可离线使用。演示数据明确标记。
3. M2 平台接入：真实健康数据读取、Watch 离线传输、平台权限和失败状态。模拟器验证不能代替真机健康接入验收。
4. M3 同账号互联：独立服务、Apple 身份、设备加入和密钥、冲突与删除测试；四端真机或对应真实账户设备联调。未通过不得宣称四端互联完成。
5. M4 发布准备：发布签名、隐私说明、资料导出和删除、可访问性、功耗、测试报告、用户验收。正式部署与上架另行确认。

本次本地开发可以推进到环境允许的阶段；开发者团队、App ID、Sign in with Apple 配置、真机和服务部署属于有名有据的外部依赖，不能用模拟成功替代。

## 执行机制

root 作为 PM 与集成人维护范围、依赖、状态和验收；产品、Apple 架构、UX agent 并行产出设计。设计确认后再分配共享核心、原生 UI、平台与同步实现的独立文件所有权。接口先确定、修改后集成，构建由集成人串行执行，避免并发工具锁。

每项任务记录负责人、输入、输出、依赖、状态、验证证据和风险。用户决定范围、费用与正式发布；PM 自主处理已批准范围内的常规实现选择。
