# 本地 AI 每日复盘

2026-11-20，用户要求本地推理，优先使用 iPhone，其次电脑，并选择首版“每日复盘与习惯建议”。本方案在已批准的原生四端、本地开发与加密账号架构内新增 AI 工作包。研究依据见 [Apple 系统模型](../research/apple-local-ai.md)、[离线模型](../research/local-model-fallback.md)与[设备路由建议](local-ai-routing-notes.md)。

本文是本轮执行基线；设备路由笔记保留前期方案比较，实际通道、结果保留方式和 Watch 范围按本文执行。当前仍在实现与验收，不能从已通过的测试或构建推定最终中文质量通过。

## 推理路径

采用系统模型优先、可下载小模型补足的原生实现。FoundationModels 需要运行时检查；本机探测已返回 deviceNotEligible，不能把 SDK 能编译当成可推理。离线备选为 MLX Swift 加载的 Qwen3-1.7B-4bit，固定 revision 为 `3b1b1768f8f8cf8351c712464f906e86c2b8269e`，完整必需资产共 984,025,460 bytes。用户主动下载后逐项验证大小和 SHA-256，再原子启用；本轮该资产已下载、校验并报告 ready，生成质量另行验收。两个平台都具备模型适配，系统版本最低线保持原方案，具体 AI 可用性单独说明。

只接系统模型的方案依赖设备／地区条件，无法覆盖当前机器；只做 Mac 推理则不足以实现手机优先。所选路径增加模型资产与 Metal 构建成本，换取 iPhone 和 Mac 均可验证的本地备选。初选 0.6B 在三次固定场景验证中仅一次通过严格结构／引用校验，不能作为稳定交付依据。更换 1.7B 后，实际原始输出分别在 29、153 token 时到达 EOS，仍未遵守 JSON 格式；这些失败没有达到 512 token 上限，不能归因于输出截断。当前据此调整生成方式，保留失败证据，不放宽 Core 校验、不猜测修正事实 ID、不自动重试直到通过。

一次请求先选择已授权且可执行的 iPhone，再选择 Mac；同类设备先系统模型，再下载模型。iPhone 只在前台、模型已就绪时承接请求，不承诺后台唤醒。未开启跨设备处理时仅在本机执行，并显示这一条件；不可达与不支持分别说明。请求已开始后发生断连不自动并发改派，避免两端重复执行。

## 复盘输入与结果

用户主动生成当天复盘。白名单包含当天的主观精力／可选心情、手动睡眠时段估算和习惯完成汇总，不含备注、习惯原名或原始 HealthKit 样本，也不提供无内容的匿名习惯明细。所有日期按明确时区，缺失留白。先由确定代码计算事实和缺失项：全日精力统计、最近三条自评、完整习惯完成汇总和主要手动睡眠估算，最多六项事实；再把这些事实送入模型。请求内部的计数元数据不进入提示词，避免把明细条数误读为天数。

Core 契约继续允许简短概述、至多三条有事实 ID 的观察和至多两条可选小习惯建议，并校验结构、长度、事实 ID、请求 ID 和输入 digest。MLX 当前采用更小的实际输出范围，分四段生成真实 AI 文本，由应用构造固定结构：

| 执行顺序 | 给模型的数据 | 模型生成的字段 | 目标／硬字数上限 | 输出 token cap | 应用负责的结构 |
| --- | --- | --- | --- | --- | --- |
| 概述 | 本次全部有效事实及缺失说明 | `overview` | 60／120 | 160 | 概述字段的位置与长度检查 |
| 观察 | 应用选定的一条确切事实 | 一条观察的 `text` | 40／80 | 96 | 一个 observation、绑定该事实的 `factIDs` |
| 建议详情 | 应用选定的一条确切事实 | 一条建议的 `detail` | 60／120 | 160 | 一个 suggestion 的详情及对应 `factIDs` |
| 建议标题 | 与建议详情相同的确切事实，以及已验证的详情草稿 | 该建议的 `title` | 12／24 | 32 | 概括该建议的名称，放入同一个 suggestion |

四段均调用真实模型；每段新建 KV cache，复用同一份已加载权重，按执行顺序分别限制 160／96／160／32 token，合计 448 token，不超过原先 512 token 的总预算。生成达到该段 cap 但尚未 EOS 时，明确拒绝截断结果，不能把不完整文字当成成功。程序负责字段、条目数量及已指定事实的关联，正文各字段仍须由模型生成。模型没有返回合格文本就显示失败，不用固定复盘代替，也不做静默 JSON 修复、猜 ID 或自动重试。FoundationModels 的结构化生成路径继续接受同一 Core 结果验证。

生成目标与硬上限分开。实际 full-day 已出现正确的 72 字概述，只因新增 60 字样式上限而被拒绝，因此保留 60 字生成目标，将概述硬上限设为 120 字；其他字段同样保留较短目标，使用表中的有界硬上限。这些上限仍低于 Core 原有长度约束，Core 的医学表达、事实引用和结构校验保持不变。建议先生成并验证详情，再让标题依据同一事实和这份详情草稿概括名称，降低两者主题不一致的风险；详情草稿仅用于概括，不能作为新增事实。

应用指定 `factIDs` 只能说明这段文本被要求依据哪条事实，不能证明生成文字与事实在语义上相符。仍须审阅是否准确复述、是否从一天记录推断长期趋势或因果、建议是否合适，以及是否出现明显医疗结论；有限规则不能保证模型安全。不要求模型重新计算真实统计，不生成疾病、诊断、治疗或压力分数。规则概览须标明未运行 AI。复盘仅在当前界面内存保存，首版不新增账号作业队列、持久历史或自动同步 AI 文本。

结果显示实际执行设备、模型、输入日期、缺失项和生成时间。用户可取消；改记录、切账号、切示例或离开生成页使旧结果失效。示例只在本机运行，不向配对设备派发。

## 设备路由与数据边界

使用 Network.framework 的局域网发现和 TLS 1.2 PSK（AES-128-GCM），不把发现当身份。Apple 的 external PSK 接口不支持 TLS 1.3；本方案遵循官方 P2P 示例，提供持钥认证与加密，但不提供前向保密，依据见本地 AI 调研。跨设备功能默认关闭；用户选择允许发送摘要及允许本设备承接任务后，才开启发现／接收。身份从当前已解锁账号 vault key 经独立用途 HKDF 派生，握手证明持有同一账号密钥；不显示、导出或把 vault key 放入 Bonjour。匿名或缺少密钥时支持本机推理，跨设备说明尚不可用。

服务只处理一个有界请求，核对版本、请求 ID、输入摘要、执行模型与当前账号代际。限制帧大小、并发、重试、超时和重复请求；停止接收或切账号关闭连接并取消任务。服务不连接云推理，现有同步服务不接收明文提示词。Mac 须运行应用，iPhone 承接限前台；局域网权限与真机后台条件独立验收。

iPhone／iPad／Mac 增加复盘入口；iPad 使用已授权的 iPhone 或 Mac。Watch 不运行模型、不下载权重，本轮保留现有轻端记录与健康功能，其独立 AI 入口和持久结果消费另列后续增量。

## 工程与验收

AI 契约、事实整理与路由位于 MyEnergyCore，局域网及运行注册位于 MyEnergyPlatform；模型和资产位于独立 MyEnergyLocalAI package，应用入口注入，避免普通 Core／UI 测试和 Watch target 链接 MLX。UI 不直接依赖模型库。

验收包含事实白名单／缺失／时区、iPhone 优先顺序、失败前后回退边界、旧请求失效、结构与证据验证、资产 hash／原子启用、真实 Mac 小模型生成、无云请求、跨设备认证与错误密钥拒绝、模型缺失和设备不可达。模拟器和注入模型不得表述为真机推理。当前两份未提交 Xcode 签名／Run 设置原样保留，构建不得直接重生成覆盖。

截至本次设计更新，已有 157 项 Swift 与 8 项 Node 回归通过；独立 Native package 的 14 个测试函数、23 个用例通过，最新资产 manifest 检查通过；Mac、iOS Simulator、Watch 的最近一轮构建通过。六项 TLS 1.2 PSK loopback 用例已通过，但没有前向保密，也没有验证真机 Bonjour／系统局域网授权。四段文本生成后的真实质量、最终构建与 UI 操作仍在进行，root 将把最终证据写入[本地 AI 验证记录](../verification/local-ai.md)，不以这些阶段结果提前完成验收。

随后四段初版的 18 个 Native 测试函数通过，属于上述目标／硬上限、详情先于标题和 EOS 检查调整前的阶段基线，不能表述为本次最终版本验证通过。
