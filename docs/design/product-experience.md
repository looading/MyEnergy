# MyEnergy 体验设计提案

状态：Proposed，待用户评审。日期：2026-11-18。MyEnergy 为工作名，正式名称、图标与角色均未定稿。

本文描述拟议体验，不代表功能已实现或平台能力已验证。当前阶段仅交付设计文档，不写应用代码、不搭建项目、不提交或发布。涉及健康数据读取、同步和留存的能力，须与平台可行性及隐私方案共同评审后进入实现。

本提案遵循[首版范围与架构提案](mvp-proposal.md)：推荐原生四端与独立加密同步服务，使用同一 MyEnergy 产品账号；M1 验收本地体验，M2 验收平台接入，M3 才验收完整互联，M4 完成发布准备。以下验收均是未来条件，当前未实现。

## 产品帮助用户看清自己的节奏

用户打开 MyEnergy，是想快速回答“我现在还有多少精力，接下来可以怎样照顾自己”。一次记录应当很轻，回顾时又能看见自己的变化。产品以中文界面为先，保留 Apple 原生导航、表单、设置和辅助功能习惯。

核心使用场景：早晨记下状态；工作间隙在手表上补记；在 iPad 或 Mac 上回顾近期记录；用一个小习惯给自己留出休息的机会。首次使用可以只有主观记录。连接 Apple 健康属于可选增强。

产品边界：精力与心情来自用户自述；HRV 等身体数据单独作为参考。MVP 不提供医学诊断、治疗建议、情绪自动识别、心理咨询或 AI 心理陪伴，也不承诺根据身体数据准确推断压力和恢复程度。

## 建议采用记录优先的方案

| 方向 | 主要体验 | 优点 | 代价与风险 |
| --- | --- | --- | --- |
| **推荐：记录优先，可选身体参考** | 精力快记、心情记录、小习惯组成日常体验，HRV 等参考放在独立卡片 | 没有手表或健康数据也能使用，用户容易分清数据来源 | 自动反馈较少，需要把记录和回顾做好 |
| 陪伴优先 | 以原创角色、轻互动和休息计时为主，记录作为补充 | 容易亲近，使用门槛低 | 角色和动画制作范围大，容易盖过用户自己的感受 |
| 数据优先 | 打开即看身体指标、历史变化和汇总 | 满足重度健康数据用户的查看需求 | 首用依赖授权和数据积累，也更容易被误解为健康判断 |

建议保留温和的原创视觉，陪伴感主要来自文案和操作反馈。角色暂不承担情绪判断，也不通过“难过、枯萎、生病”等状态催促用户记录。

## 主观感受与身体数据各自表达

| 信息 | 拟议表达 | 使用约束 |
| --- | --- | --- |
| 主观精力 | 用户在 `0～100` 范围内自行选择，整数保存 | 始终标“主观自评”，例如“我记录的精力：65／100”；不与身体指标合成 |
| 心情 | 可选五档：“很不愉快、不太愉快、一般、比较愉快、很愉快” | 五档措辞待文案评审；不从精力选择自动填入，允许跳过和后续修改 |
| 简短备注 | 可选自由文本 | 默认不出现在通知、桌面预览或手表状态页 |
| 小习惯 | 用户选择或自定义的一项小事，手动完成 | 不从健康数据自动宣称完成；不累计惩罚性连续天数 |
| HRV | “心率变异性（HRV）”，数值、单位、来源、采样时间 | 独立展示；不命名为“心情、压力值、能量值” |
| 其他健康参考 | 静息心率、睡眠摘要；在平台支持和用户按需授权后显示 | 每项单独说明来源和时间；可缺失，不补造 |

同一天允许多次主观记录。今日页显示最近一次及时间，趋势页保留当天全部记录。精力高低与心情可以出现任何组合，界面不得纠正、质疑或覆盖用户选择。

身体参考首先展示最近指标和时间。HRV 仅在满足经过评审的数据充分条件后，展示与个人历史的对照；样本不足显示“正在积累数据”。基线时间窗、过滤、阈值和算法版本由恢复参考子项目确定。MVP 不生成合成“恢复分”“身体电量”或自动情绪判断。

## 各设备围绕各自常用场景安排

| 平台 | 主要任务 | 主导航 | 内容组织 |
| --- | --- | --- | --- |
| iPhone | 记录、查看今日、管理习惯和授权 | 底部“今日／趋势／习惯／我的” | 单列卡片，详情进入原生导航页，快记使用独立表单 |
| iPad | 查看较长趋势、对照记录、编辑 | 侧栏沿用相同栏目 | 主内容看板，可展开所选记录详情；窄窗口回到单列 |
| macOS | 工作间隙快记、查看趋势、整理记录 | 原生侧栏与工具栏 | 今日看板和趋势主区；选中记录后显示详情，支持键盘 |
| Apple Watch | 少量操作快速完成 | “精力快记／习惯／状态”纵向列表 | 每屏只完成一件事，使用整行点击区和 Digital Crown 滚动 |

栏目名称跨平台一致，布局按屏幕空间变化。Mac 与 iPad 不把手机页面等比例放大；手表不承载长备注、复杂图表或数据管理。

MVP 采用 Mac 主窗口，不同时扩展菜单栏常驻、小组件和复杂多窗口。Watch 默认作为 iPhone companion，由配对手机完成必要配置；手表离线记录进入本地队列，不承诺独立注册或直接连通 Mac／iPad。

## 今日页把快记放在最前面

### iPhone 今日页

从上到下的信息顺序：

| 区域 | 主要内容 | 主要动作 |
| --- | --- | --- |
| 顶栏 | “今日”、日期、同步状态入口 | 查看同步详情 |
| 精力卡 | 无记录时“现在感觉怎样？”；已有记录时显示主观精力和记录时间 | “记一下”或“再记一次” |
| 可选心情 | 最近一次记录中的心情；未填写时仅在记录详情中邀请补充 | 查看或编辑记录 |
| 今天的小习惯 | 最多预览三个启用习惯，已完成状态清楚可撤销 | 完成、撤销、进入全部习惯 |
| 身体数据参考 | HRV 等已连接指标的最近数据及时间 | 查看详情、了解数据、管理连接 |
| 今日记录 | 按时间倒序的记录列表 | 查看、编辑、删除 |

“精力卡”和“身体数据参考”之间保留明确的标题分隔。身体数据缺失时，不占据大面积空白仪表盘，也不替换用户的主观记录。

原型文本示意：

```text
今日                                已同步 · 10:42
11 月 18 日，星期三

我记录的精力：65／100
你在 10:40 记录                         再记一次

今天的小习惯
○ 起身走一走       ✓ 给自己留点空闲

身体数据参考
心率变异性（HRV）     [来自实际数据的数值] ms
最近一次采样：[实际日期与时间]
这些数据与“我的精力”分开展示             查看详情

今日记录                               查看全部
10:40  精力 65 · 心情一般
```

原型占位文字不作为演示数值，更不能出现在真实数据界面。生产页面缺少有效样本时，显示明确空状态。

### iPad 与 Mac 今日看板

侧栏右侧保留稳定的阅读主区。空间允许时分为两列：宽列放精力卡、今日记录；窄列放小习惯和身体数据参考。窄窗口自动回到单列，阅读顺序与 iPhone 一致。

记录列表选中一项后，在详情区显示精力、心情、备注和发生时间，再提供编辑或删除。切换栏目时保留列表位置，避免用户每次从第一条重新找起。

### 手表首页

首项为“精力快记”，下方显示最近一次主观记录及时间；后续为“习惯”和“状态”。快记可选填五档心情，长备注留到其他设备补充。状态页只显示本人记录摘要及明确的同步状态。健康指标在手表上的可用范围按平台评审决定，不以动画或颜色假装实时测量。

## 快记只要求选择一次精力

**入口 → 选择精力 → 可选心情／备注 → 保存反馈。**

手机和平板：打开表单后展示 `0～100` 的原生滑杆与当前选择值，允许逐点调整，端点解释为“几乎没有精力／精力很充足”。默认处于未选择状态，布局使用的滑杆初始位置不得自动当作用户记录；用户明确选择后才能保存。心情和备注保持可选。保存使用原始记录时间，不把编辑时间当成新发生时间。取消有内容的表单时提供“继续编辑／放弃”选择。

Mac：工具栏“记一下”和 `⌘N` 打开同一流程。键盘可以依次聚焦选项、表单和保存；`Esc` 关闭表单，有未保存内容时先确认。

手表：点击“精力快记”，使用 Digital Crown 或可聚焦的增减控件在 `0～100` 范围选择整数，再点击“保存”。心情使用可选的五档整行列表，备注留到其他设备补充。保存后显示“已保存在手表”，并单独标明是否已同步。

保存成功使用轻量反馈，避免全屏庆祝。不得把“本机已保存”显示为“所有设备已更新”。保存失败时保留选择和输入，让用户重试。

## 趋势页让缺失数据保持可见

默认查看最近七天，可切换最近三十天。精力记录、心情记录和身体参考分区查看，不合成为一条曲线。

- 精力采用按时间排列的离散点，纵轴为 `0～100`，明确标“主观自评”。多次记录都可查看，用户主动选择的 `0` 与未记录日分别表示。
- 心情采用按日期排列的五档记录摘要，保留文字。MVP 不计算“快乐率”、情绪诊断或情绪排名。
- HRV 等参考只连接真实存在且符合展示条件的采样；缺口保留。每张图注明指标、单位、时间范围、来源和最近更新时间。
- 点选图中记录后出现对应时间与原始内容；辅助功能用户可切换到同等信息的列表。
- 没有足够记录时显示“记录会慢慢出现在这里”，同时提供“记一下”。只有一条记录时展示单点，不生成趋势判断。

日期分组拟统一按当前查看设备的时区计算。详情保留原始发生时间与记录时区；切换时区不得复制或删除记录。跨时区的习惯归属日规则须在实施前与数据模型统一，并用旅行和午夜场景验证。

## 小习惯保持轻量可退出

首次进入时展示少量可选示例，例如“起身走一走”“给自己留点空闲”，用户也可以输入自己的习惯名称。默认不自动启用，不发送提醒。

今日页最多预览三个日常习惯，其余进入完整列表。习惯可以创建、编辑和停用；每项只有“未完成／已完成”，完成后可撤销，停用不删除历史。初版按每天展示，不扩展复杂周期、挑战榜、积分或付费打卡。

提醒可作为后续扩展：在用户主动设置时间后才请求通知权限，拒绝后仍可完成习惯。若后续加入一分钟安静计时，默认安静、允许随时结束，也不记录所谓放松效果；计时和提醒均不作为当前 M1～M4 的验收前提。

## 首用先完成记录，再决定连接

欢迎页只解释两件事：“记下自己的精力，慢慢看见变化”“可以稍后连接 Apple 健康”。主动作“开始记录”，次动作“先看看示例”。不得把健康授权或同步账户作为进入门槛。

首次保存记录后，才出现可关闭的连接说明。用户也可以之后在“我的”中连接。

**连接健康数据：** 先说明拟读取哪些数据、各自显示在哪里，以及跳过后仍可使用的功能。用户点击“连接 Apple 健康”后，才进入系统授权。每一类权限都要与当前功能对应，MVP 不请求写入权限。授权结果回到 App 后，区分“已有可读数据”和“暂无可显示数据”；不得把读取结果为空断言为用户拒绝权限。

**开启设备同步：** M3 的推荐方案为同一 MyEnergy 产品账号，建议使用 Sign in with Apple，记录通过独立加密服务同步。界面先说明精力、心情、备注、习惯及相关设置的同步范围，再提供“使用 Apple 登录”。未登录时可“先在本机使用”。新增设备须完成已批准的设备确认或恢复流程；登录身份不等于已经取得解密密钥，缺少密钥时单独解释下一步。

同一 MyEnergy 账号下，各设备可以有不同的健康数据可用范围。健康摘要同步须单独取得用户同意，不因登录或同步本人记录而自动开启；撤销同意后停止新上传，并提供删除已同步摘要的路径。原始健康样本留在 Apple 健康，不对健康记录启用 CloudKit 同步。Mac 只展示用户同意同步且能解密的摘要，并注明“来自其他设备的摘要”和实际测量时间；摘要不可用时仍正常显示本人记录。

## 示例数据始终有明显边界

示例模式默认关闭，只从用户主动选择的“先看看示例”或“我的 → 查看示例”进入。

- 全屏持续显示“示例数据”标识，退出入口始终可见。所有参考图表也标“示例”，不能只在首屏解释一次。
- 示例使用单独的数据空间，不请求健康权限，不写入真实记录，不同步到用户设备，不与真实记录混合计算。
- 退出后回到真实数据空间，恢复原有空状态或真实内容。用户在示例中尝试记录时，只提示“已添加到示例”，并提供进入真实记录的明确入口。
- 手表状态页和未来的小组件不得把示例伪装成本人状态。MVP 不向这些外部展示位置提供示例数据。

## 同步状态要让用户知道记录在哪里

顶栏使用简短状态，点击后展示详情。状态变化保持安静，只有阻止当前操作的问题才使用弹窗。

| 场景 | 用户可见内容 | 可继续的操作 |
| --- | --- | --- |
| 已同步 | “已同步 · 10:42”，详情显示最后成功时间 | 正常查看和记录 |
| 本机已保存 | “待同步”，详情为“已保存在此设备，其他设备稍后更新” | 查看、继续记录 |
| 正在同步 | “正在同步”，有待传内容时说明本机已保存 | 正常使用，不锁住页面 |
| 离线 | “离线 · 记录已保存在此设备” | 本机记录、编辑、习惯完成 |
| 尚未登录产品账号 | “仅保存在此设备”，说明使用同一 MyEnergy 账号后可加入同步 | 本机使用、主动登录 |
| 已登录但尚未完成设备确认 | “等待设备确认”，说明记录仍在本机 | 按批准流程确认设备或恢复密钥，不假装已同步 |
| 同步受限或失败 | “同步暂不可用”，详情给可核实的原因和重试入口 | 保留本机内容、稍后重试 |
| 云端尚未加载 | “正在读取其他设备的记录” | 本机内容立即可见；不得把未加载当作零条历史 |
| 本机上传成功，其他设备尚未接收 | “已上传”，详情说明“其他设备会在可用时更新” | 查看本机内容，不显示所有设备已收到 |
| 同一记录出现编辑冲突 | “这条记录在其他设备也有修改”，并列展示两份内容 | 用户选择保留版本，未选择前不丢弃任一份 |
| 账户切换 | 说明当前同步空间已改变 | 原账户内容不得默认显示给新账户；合并前须明确选择 |
| 手表尚未传出记录 | “已存手表，待同步” | 在手表查看和继续记录 |

同步延迟不承诺固定秒数。界面将“本机已保存、已上传、当前设备已获取最新变更”分别表达；“已同步”仅代表当前设备完成与服务的本轮同步，不能代表所有设备已收到。重试和重复传输不得制造重复记录。删除也需要同步，不能在另一台设备重新出现已删除内容。完整互联在 M3 通过前不得以演示成功代替。

## 无健康数据时给出准确说明

| 场景 | 主要文案 | 提供的入口 |
| --- | --- | --- |
| 用户尚未主动连接 | “可以连接 Apple 健康，查看身体数据参考” | “了解并连接”“稍后” |
| 读取结果为空 | “暂时没有可显示的数据” | “了解数据来源”“管理健康连接” |
| 当前设备或平台不支持批准的读取路径 | “此设备暂不能显示这项身体参考” | 查看说明；继续使用本人记录 |
| 最近样本较早 | “最近一次采样来自［日期与时间］” | 查看详情；不得显示为当前即时状态 |
| HRV 个人历史不足 | “正在积累数据”，可用的原始样本仍可查看 | 解释历史对照的积累条件，不生成基线结论 |
| 某项数据存在，另一项缺失 | 有数据的指标正常显示，缺失项独立提示 | 分别管理对应连接 |
| 健康读取出错 | “暂时无法读取，稍后再试” | 重试，保留本人记录 |
| 用户关闭健康连接 | 停止后续读取，并移除 App 中的对应临时展示 | 重新连接、查看删除说明 |

缺失值不显示为零，不用空心电池或红色警报暗示身体异常。健康参考卡的数值与原创视觉角色之间不建立自动情绪映射。

## 视觉使用温和绿色和暖米白

视觉方向为安静、清楚、有留白。使用原创的抽象圆润形态，例如带小叶片的绿色形状，暂不确定角色名称。避免沿用竞品角色轮廓、五官、表情、插画或布局细节。

主视觉可以随用户刚刚选择的主观精力呈现轻微姿态变化，旁边明确写“来自你的记录”。未记录时保持中性。角色不映射健康数据，不出现惩罚、衰败或索要照顾的表情。

以下为浅色方案的设计 token 建议，等待视觉评审。实现时使用语义化颜色并验证深色、高对比度和系统辅助设置，不能把这些色值当作所有模式的固定结果。

| Token | 拟议值 | 用途与限制 |
| --- | --- | --- |
| `background.canvas` | 暖米白 `#F8F7EF` | 页面背景，避免全屏高亮纯白 |
| `background.surface` | `#FFFFFF` | 主要卡片和表单表面 |
| `content.primary` | 深绿黑 `#1C2E24` | 正文、关键数值 |
| `content.secondary` | 灰绿 `#536258` | 时间、来源和辅助说明；须达到文字对比度目标 |
| `action.primary` | 森林绿 `#2F624A` | 主要按钮和选择状态，搭配白字后验证对比度 |
| `accent.soft` | 浅鼠尾草绿 `#DCE9D8` | 选项和插画背景，不承载低对比文字 |
| `border.subtle` | `#D7DED4` | 非必要装饰分隔；控件边界需另行保证可辨认 |
| `status.attention` | 使用系统警示色并配文字 | 仅表示实际操作问题，不表示心情等级 |
| 字体 | Apple 系统字体，中文跟随系统字形 | 正文以原生 body 为基准，标题不依赖自带艺术字 |
| 间距 | `4／8／12／16／24／32 pt` | 卡片内优先 `16 pt`，相邻区块优先 `24 pt` |
| 圆角 | 卡片建议 `20 pt`，小控件 `12 pt` | 系统按钮和表单优先沿用平台形态 |
| 动效 | 建议 `150–220 ms`，幅度小 | 减少动态效果开启后改为静态反馈，不持续脉动 |

不为每种精力分配红黄绿健康等级。文字标签、选中标记与位置共同表达状态，用户不必依赖颜色或角色表情。

## 辅助功能进入验收范围

- 触控区域以至少 `44 × 44 pt` 为设计目标，手表使用整行选择；重要动作有清晰文字，图标不承担唯一解释。
- 支持系统文字大小。最大辅助字号时看板回到单列，正文与按钮完整换行，关键数值和单位不会截断。
- 普通正文对比度以 `4.5:1` 为目标，大字号文字和必要图形以 `3:1` 为目标。浅色、深色和高对比度设置分别验证。
- VoiceOver 的朗读顺序与页面视觉顺序一致。精力项示例：“主观精力，65，范围 0 至 100，可调整”；参考项须朗读指标、数值、单位和采样时间。
- 趋势提供可读列表，与图形包含同样信息；缺失数据也要朗读出来。
- Mac 全流程可用键盘完成，焦点始终可见，关闭表单后回到入口。支持 `⌘N` 快记和 `⌘,` 打开设置。
- 开启“减少动态效果”后不播放循环呼吸、漂浮或缩放。选择与保存仍以清楚文字表示，触觉反馈可关闭。
- 静音、色觉差异、没有触觉反馈或未启用健康连接时，核心记录流程仍能完成。

## 隐私设置说明实际会发生什么

“我的”集中放置健康连接、设备与同步、通知、显示与辅助选项、数据管理、关于。每个入口使用用户能理解的对象名称，不把存储服务名放进日常使用流程。

MVP 的拟议隐私默认值：不自动开启健康读取和通知；不加入第三方行为分析；不把精力、心情、备注和健康数值放进日志或崩溃说明；通知只显示用户明确同意的通用提醒文字。设备同步范围应在开启前解释，不能用“同账号互联”代替数据说明。

健康数据的本地缓存、保留时长、跨设备路径及任何派生数据同步，均为需批准的架构和隐私决策。依照主方案，不对健康记录启用 CloudKit 同步，也不承诺健康数据在全部设备上天然可见。

数据管理提供以下拟议行为：

| 动作 | 操作前说明 | 操作后反馈 |
| --- | --- | --- |
| 删除单条本人记录 | 明确显示记录日期和类型，使用系统删除确认 | 列表立即更新；同步状态可追踪 |
| 关闭健康连接 | “停止读取，并清除 MyEnergy 内的临时展示；Apple 健康中的原始数据会保留” | 参考卡恢复未连接状态 |
| 导出本人记录 | 导出精力、心情、备注和习惯记录，说明文件含个人信息 | 通过系统文件或分享流程交给用户，不自动上传 |
| 删除 MyEnergy 全部记录或账号 | 说明本人记录、习惯、已同步摘要及 App 副本范围；账号删除另说明登录身份和服务数据的处置，原始健康数据不在此范围 | 显示删除处理状态，其他设备恢复同步后应用删除 |
| 退出示例 | 说明示例内容不会保存到本人数据 | 回到此前的真实空间 |

全部删除须有独立确认页。离线时明确说明云端删除尚待处理，不能提前宣称全部设备清除完毕。删除方案须避免离线旧副本恢复后重新上传。系统备份、导出文件和 Apple 健康原始数据的管理边界，须在最终隐私说明中写清楚，不承诺无法验证的彻底擦除。

## MVP 先交付完整的日常闭环

| 优先级 | 范围 | 完成边界 |
| --- | --- | --- |
| 必须 | 四个平台的原生导航与今日入口 | 各自适配，中文可读，完成核心快记 |
| 必须 | 主观精力、可选心情与备注 | 本机保存、编辑、删除、今日列表 |
| 必须 | 七天／三十天趋势 | 原始记录可追溯，缺失数据可见 |
| 必须 | 手动小习惯 | 创建、编辑、停用、完成、撤销；今日最多预览三项 |
| 必须，M3 | 同一 MyEnergy 账号的 App 记录同步 | 独立加密服务；明确设备确认、离线保存、重试、冲突和删除传播 |
| 必须，M2 | 可选身体数据参考 | 支持的平台读取 HRV、静息心率、睡眠摘要；显示来源、单位、时间、样本充分性与空状态 |
| 必须 | 隐私与数据管理 | 按需授权、停止读取、导出本人记录、删除 App 数据 |
| 必须 | 独立示例模式 | 持续标识、不混入真实空间、不发起同步 |

| 后续评审 | 更多健康指标、安静计时与提醒 | 按变更流程确认范围，避免扩大首版 |

MVP 不要求所有平台读取同样的健康数据。M3 才验收本人记录、习惯和明确同意的摘要在批准同步路径上互联；健康数据按平台能力呈现，并为不支持的设备提供准确说明。首版不加入收费、广告或第三方 AI 陪伴。

## 验收以用户能完成的行为为准

以下均为拟议验收条件；实施后需要运行结果或交互证据支持，不能以设计文档存在代替完成。

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| UX-01 | 新用户未连接健康、未开启同步 | 四个平台允许进入核心页面；已完成必要初始化的设备可保存主观记录，不出现伪造分数 |
| UX-02 | 用户记录“精力 90、心情很不愉快” | 精力整数与五档心情独立保存和展示；健康读数变化不会覆盖选择 |
| UX-03 | 用户只选择精力 | 可直接保存；未填写的心情和备注保持空值，系统不推断 |
| UX-04 | 同日多次记录、随后编辑一条 | 全部记录可找回；编辑保留原始发生时间，列表和趋势同步更新 |
| UX-05 | HRV 无样本或没有可读结果 | 显示“暂无可显示数据”及相关入口；不显示 `0 ms`、低分或拒绝授权断言 |
| UX-06 | 仅存在较早的健康样本 | 明确显示采样日期和时间，不标为实时状态，不驱动角色表情 |
| UX-07 | 设备离线后保存并重启 App | 已保存内容仍可见，状态为本机保存／待同步；联网后重复传输不产生重复记录 |
| UX-08 | 两台设备同账户同步 | 一端新建、编辑、习惯完成和删除可在另一端收敛；收到成功确认前不显示“已同步” |
| UX-09 | 手表离线快记 | 保存反馈明确指向手表本机；连接恢复后同步，用户无需重复填写 |
| UX-10 | 账户退出、切换或同步受限 | 原账户内容不会默认暴露给新账户；本机内容不被无提示丢弃，合并需用户明确选择 |
| UX-11 | 同一记录在两端修改 | 两份内容均保留到冲突处理完成，用户能辨认各自修改并选择 |
| UX-12 | 示例进出及尝试记录 | 始终能辨认示例，真实数据不变化，不触发健康读取或跨设备同步 |
| UX-13 | 关闭健康连接 | 停止后续读取，临时展示清除，原始 Apple 健康数据保留；本人记录继续可用 |
| UX-14 | 删除全部 App 记录，另一设备离线 | 明确显示传播尚未完成；离线设备恢复同步后应用删除，旧内容不重新出现 |
| UX-15 | 最大辅助字号与 VoiceOver | 精力可从 `0` 调整到 `100`；核心按钮、标签、单位和时间完整可读；图表有等价列表 |
| UX-16 | Mac 仅键盘操作 | 可新建、选择精力、保存、查看详情和删除；焦点无丢失或无法退出的区域 |
| UX-17 | 深色／高对比度／减少动态效果 | 对比度满足目标，状态不只靠颜色，选择与保存反馈无需动画也能理解 |
| UX-18 | 用户停用习惯 | 历史记录仍可查看，不自动恢复习惯，也不通过羞辱性文案催促 |
| UX-19 | 当前设备无法显示健康参考 | 今日、趋势及习惯仍可使用，准确说明设备限制，不把缺失当成异常身体状态 |
| UX-20 | 午夜和跨时区查看 | 无重复或丢失记录；日期分组与详情时间遵循最终批准的统一规则 |

## 评审先确认产品取舍

建议本轮确认：以“记录优先、身体参考可选”为产品方向；采用温和绿色与暖米白的原创视觉；同一 MyEnergy 账号通过独立加密服务同步，健康摘要另行征得同意；四个平台保留不同深度的操作；HRV 只作为独立数据参考。

进入实现前还需统一：健康数据可用平台和留存方案、同步账户及冲突处理、跨时区的习惯日期规则、正式名称与角色方向。上述内容应由产品、技术和隐私方案共同形成批准结论；本文不替代批准，也不将任何未验证能力写成现有功能。
